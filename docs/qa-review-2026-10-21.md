# QA review — October 21, 2026

Environment: Windows, Node.js 24.21, Python 3.12. Tests used disposable projects and separate progress storage. The learner's project and progress were not edited.

## Results

- Full existing automated suite: **35 test groups passed**, zero failures, approximately 233 seconds. This includes reference implementations and rejection of do-nothing implementations across all 11 courses.
- The suite explicitly reported 49 Shell stages as unsupported on Windows. Those require a POSIX environment or a pseudo-terminal and remain unverified here. These are diagnostics inside a passing test group, not top-level skipped tests. The terminal-specific half of grep's automatic-color check also needs Linux/macOS.
- Three additional QA regressions passed: project-specific stage results, run-summary publication order, and disabled-extension validation. Six targeted checks passed when these were run again alongside the answer-response regressions.
- All 11 Python starters initialized through the CLI, compiled with Python, and displayed their first-stage instructions.
- All 412 answer endpoints returned either a valid Python answer or an explicit unavailable message.
- Browser checks covered catalog, course instructions, answer expansion, unavailable answers, help, test history, and keyboard navigation into run details. No browser errors were observed in the checked flows.
- End-to-end isolated learner check: Python Redis stages jm1 and rg2 passed through the CLI; progress advanced to wy1; live logs and the completed result appeared in the browser; the expanded answer remained visible after refresh. Live drawer collapse and close worked.
- JavaScript syntax and Git whitespace checks passed.

## Fixes made

1. Stage results are now matched to the active project directory. Previously, results from another project in the same course could appear under the learner's stage.
2. The finished-run summary is saved before publishing the completion event. Previously, the live dashboard could refresh before the summary existed and show an older result.
3. `test --stage <disabled-extension-stage> --previous` now reports an actionable error. Previously, it could select zero stages and report success.
4. Navigation responses are guarded by a route version. Responses from an older navigation cannot overwrite a more recent page, including errors and run-detail responses.
5. Unknown run IDs show Page not found instead of an empty run-detail screen.
6. Test-history entries now contain keyboard-accessible links to the run details.

## Remaining coverage limits

- Only seven Redis base stages have authored Python answer diffs. The other 405 stages have instructions/testers but no Python answer yet. This is unfinished content, not a blank-panel rendering error.
- Passing the tester reference suite is not proof of production-level protocol completeness or that every incorrect implementation will be rejected.
- Windows-only review: Linux/macOS/WSL, desktop packaging, and live external model providers were not tested. The Claude Code tester suite uses its local mock model.
- At the time of this review, changes were local. Repository publication is tracked separately in Git history.
